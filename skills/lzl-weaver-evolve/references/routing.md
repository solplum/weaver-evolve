# 环境发现与知识路由

在确定来源、写入位置或解决层级冲突时读取本文件。

## 发现顺序

1. 用户当前指定的路径、项目、资料及授权；当前任务已加载的环境规则与能力。
2. 可用专用接口提供的项目、历史、记忆及知识库信息。连接器适用时优先用连接器。
3. 目标项目及父级实际适用的指令文件、现有知识索引和配置。环境声明的主目录或配置变量可以提供定位线索；只读取所需变量，不输出整份环境或凭据。
4. 在上述已知位置做小范围发现。未知目录和无法验证的格式进入未覆盖清单，不枚举整个用户目录来猜测。

发现的是同一套流程的运行上下文，不创建按产品命名的版本、目录树或规则分支。遵循当前拥有者的路由；未发现全局记忆或知识库时，不自造一套替代体系。

## 按内容和范围选择落点

| 内容 | 目标 | 保留的关键信息 |
|---|---|---|
| 跨项目执行约束 | 当前环境实际使用的全局指令 | 可执行规则、适用条件 |
| 项目／模块执行约束 | 对应范围实际生效的项目／子目录指令 | 最近适用层级、例外范围 |
| 跨项目稳定偏好 | 当前环境支持的全局记忆或用户既有偏好记录 | 用户原意、范围、明确性 |
| 项目决策与背景 | 项目现有文档或记忆机制 | 决策、理由、前提、来源 |
| 通用方法与概念 | 既有知识库或方法文档 | 使用条件、步骤、成功证据、限制 |
| 错误与已验证解法 | 项目既有复盘／错误记录 | 症状、根因、修复验证、预防价值 |
| 易变运行状态 | 现有任务记录／状态文档 | 观察时间和实际验证结果，不提升为永久约束 |
| 真实配置变更 | 拥有者定义的配置位置或接口 | 当前请求涵盖配置修改、字段已验证 |

全局偏好不必变成强制规则；通用方法也不必来自多个项目。将用户明确决定写成“偏好”还是“约束”，以用户用语和当前协作规则为准。

## 拥有者优先

- 普通用户维护文档：按原结构更新并检查引用。
- 托管／自动生成记忆：使用拥有者指定的 API、命令或增量笔记机制，不改生成索引或摘要正文。
- 外部系统、只读资产：读取和提案；实际修改必须通过可用接口且在当前授权内。
- 没有受支持落点：保留待处理项，说明缺少哪项定位或权限；不得报告已保存到长期记忆。

## 比较冲突

先核对同一对象、同一条件、同一层级，再比较时间和证据。例如“默认使用工具 A”与“项目 B 使用工具 C”可以同时成立；“尝试方案 D”不是“已决定采用 D”。助手提议即使出现在更晚的对话中，也不能覆盖用户的明确决定。

用户同范围明确推翻旧决定时，更新原条目，并检查已知引用、关联项目及索引。无法访问的关联位置列为未完成，不能因为主文件修改成功而标记全部完成。
