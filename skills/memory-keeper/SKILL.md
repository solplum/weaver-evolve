# 记忆管理

保存用户明确指定的信息，或整理已有记忆。独立使用；受 `lzl-weaver-evolve` 委派时，沿用其来源、目标和授权范围，返回逐项结果，不扩大历史扫描。

## 先识别记忆的拥有者

读取当前生效的规则、已提供的环境说明和目标存储规范，确定记忆由谁维护：

- **平台或工具托管、自动生成**：通过指定的记忆接口、增量笔记或变更入口更新。禁止直接改写生成产物；没有受支持写入入口时，仅返回可执行建议。
- **用户维护的文件或知识库**：沿用现有目录、索引、链接与写入约定。
- **位置未知**：先搜已知索引和明确相关位置；仍无法判断时只询问影响落点的关键信息。

规则文件保存未来执行需要遵循的约束；全局记忆保存跨项目稳定偏好；项目记忆保存项目决策与上下文；通用方法进入现有知识库。配置变更不是记忆写入的替代方式，仅在用户请求包含配置修改时执行。敏感资料使用用户已选的专用存储，普通记忆保留必要引用。

## 记住

1. 将请求提炼为可独立更新的事实或偏好，记录适用范围、时间条件和来源。用户的明确选择无需等待重复出现；推测保留为待验证项。
2. 在候选目标、索引和已知关联位置搜索同义表述、旧版本与例外。读取匹配内容，决定新增、更新、合并或无需变更。
3. 冲突先比较对象、范围与生效条件，再比较时间。同一项目的例外不自动推翻全局偏好；不同范围的规定可以同时保留。事实真伪不确定时不靠缩小范围解决。
4. 按现有结构融入权威记录，并同步已知依赖它的摘要、索引和链接。历史设计可保留为历史，不能继续标成当前事实。
5. 通过实际写入入口读回，确认保存的是请求内容，旧的当前表述已处理，链接与索引一致。已有内容完全覆盖请求时报告无需写入。

只执行当前请求明确或合理包含的操作。已有明确授权的同批具体操作直接完成；范围不清、存在实质冲突或需要扩大操作时，集中展示目标和待决事项后一次询问，不逐条重复确认。

## 忘掉

1. 在用户指定存储和已知关联位置定位匹配事实、摘要、索引及派生规则，区分同名但无关的信息。
2. 请求已经明确对象和范围时，精确移除；存在多个可能对象时先列出差异，澄清后再处理。
3. 使用存储拥有者支持的删除或更正入口，同步索引与引用，保留无关内容。
4. 再次搜索同义表达并读回结果；列出受控范围内的残留及原因。不能据此宣称外部系统、备份或版本历史也已擦除。

## 整理已有记忆

默认整理现有内容，不顺手从未授权历史补充新事实。检查重复、冲突、当前状态过期、放错层级、死链与失效索引。

- 同义且同范围：保留权威版本，合并有价值的证据。
- 同主题但用途不同：保留各自职责，用链接连接；不要为去重删除面向不同受众的必要说明。
- 适用范围明确放错：提出迁移位置，并更新关联引用。
- 只是无法访问或缺少近期验证：标记待核实，不直接判作过期并删除。

需要判断合并、例外或删除时，读取 [合并案例](references/merge-examples.md)。

## 完成结果

报告实际使用的存储、已处理／无需变更／待确认事项及验证结果。文件存储用修改前后差异或受限路径的版本差异检查范围；非文件存储使用接口回执与读回结果。被委派时附来源标识，方便上层保留未完成项。
