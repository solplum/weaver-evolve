# 错误复盘

从真实故障中提取可复用的诊断与预防知识。实时故障尚未定位时先报告待验证假设；复盘请求不自动授权修代码、修改运行配置或技能。

## 1. 识别范围、来源与落点

- 使用用户指定的项目、日志、提交或时间范围。受 `lzl-weaver-evolve` 委派时只使用传入的证据范围，并返回每项处理状态。
- 读取当前生效规则及项目已有复盘、错误日志或知识索引。沿用现有存储；没有时给出有内容的候选位置，不创建代理专属目录来适配平台。
- 用户请求归档复盘且落点明确时可写入；只要求分析时交付分析。托管或自动生成记忆仅通过当前环境指定入口更新。
- 历史数据是可选来源。优先使用已提供日志、修复结果、相关提交和项目文档；需要补查历史时先识别可用来源与实际格式，不能扩大为全部对话扫描。

## 2. 建立故障事实

每个故障记录症状、影响、发生条件、来源、修复动作及验证结果，使用能定位的文件、事件或提交引用。只保留必要日志片段，不复制密钥和无关私人内容。

排除预期异常、测试故意失败与文档示例。合并同根故障的重复输出；区分独立故障、环境临时失败和真实代码缺陷。必要时读取 [常见调查方向](references/error-patterns.md)。

## 3. 分析根因与价值

对每个值得归档的故障回答：

1. 哪个条件直接触发失败？
2. 哪个假设、接口或流程导致该条件未被正确处理？
3. 哪种最小验证能够确认根因，并证明修复解决原故障？
4. 哪项有适用条件的做法能减少再次发生？

根因与修复状态分别标注：确定／推测，已验证修复／未验证／未修复。命令退出成功不能替代目标行为验证。

- 根因明确且有复用价值：归档原因、证据和预防建议。
- 根因明确但一次性：按项目需要简记，不提升为全局规则。
- 证据不足但值得追查：保留假设与最小验证方法，不能作为确定规则。
- 无实际价值或重复输出：说明排除理由，不为凑条目归档。

一次高价值故障可形成有条件的方法；重复次数只增加证据，不是提炼的必要门槛。

## 4. 去重与关联

搜索已有错误记录、规则和技能中的同根问题。更新权威条目的证据与状态，维护已知索引和关联记录；一个项目的特殊故障不自动上升为所有项目禁令。

怀疑技能流程造成故障时，读取 [技能审查指南](references/skill-audit-guide.md)，定位实际缺口并给出可验证改法。没有证据时不要为假想故障堆叠规则。

## 5. 归档与改进

在适用的现有格式中保留：

- 时间、范围和症状；
- 直接原因及证据强度；
- 修复与实际验证；
- 预防方法、适用条件、来源和关联记录。

具体归档在用户授权范围内直接完成。需要修改规则、配置、代码或技能时，将具体目标、理由与验证方式集中展示；已有同批明确授权就继续执行，其余作为待决项。使用最窄适用范围，维护既有结构。

## 6. 验证与报告

通过拥有者支持的入口读回记录，检查事实与推测未混淆、修复状态符合证据、索引和引用有效。用受限路径的版本差异、前后清单或接口回执核对实际变更。

报告核心根因、已归档／无需归档／待验证事项、使用的数据源和未覆盖范围。无真实故障时说明扫描范围与结果，不宣称全局无错误。
