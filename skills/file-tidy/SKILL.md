# 文件归位

学习已有结构，整理明显放错位置的文件。独立使用；受 `lzl-weaver-evolve` 委派时只处理给定目录和候选，将逐项结果返回上层。项目架构重构不属于普通归位。

## 1. 确定范围与既有结构

- 使用用户指定目录；未指定时检查当前目录并说明范围。跨目录或递归处理以用户请求和当前授权为边界。
- 读取当前生效的目录规则及目标根的 `.tidy-rules.yaml`（若有），配置仅补充语义。
- 记录文件清单及已有改动；有版本控制则记录受限范围的状态，没有则使用文件元数据或哈希。
- 检查直接子目录用途、少量文件样本、项目入口和依赖清单。独立子项目内的结构保持不动，除非明确纳入范围。

存在 `.tidy-rules.yaml` 时读取 [配置格式](references/rules-schema.md)，不因配置文件不存在而要求新建。

## 2. 识别归位与删除候选

默认只检查目标目录直接散落的文件。依据内容主题、已有目录职责和相关文件聚集判断位置；扩展名仅是辅助证据。

- 高置信度：用途和已有目录明确对应，目标唯一，已知引用可保持或在授权范围内同步更新。
- 待判断：多个可能目标、内容不足，或移动需要额外修改调用方。
- 保持原位：入口、许可证、依赖清单、锁文件、规则文件、工具自动发现文件，以及根目录中职责明确的产物。

保护版本元数据、当前代理的配置/记忆/技能目录、依赖和构建缓存、凭据与数据库。符号链接不作为普通文件移动；并行修改或所有权不明的文件暂留。

临时后缀或“备份”字样只提供清理线索，不证明文件无用。删除候选需要说明它为何可丢弃、是否仍被引用，以及可恢复来源。

## 3. 展示并落实授权

用一张表列出：编号、源路径、动作、目标路径、依据、引用调整和待决问题。区分高置信度移动、待确认和建议删除。

- 检查/建议请求只产出计划。
- 用户已明确授权同批具体移动或删除时直接执行，无需重复确认。
- “自动整理”足以执行范围内可逆的高置信度归位；删除、覆盖、扩大范围和结构重构需要具体授权。
- 由上层委派时继承其明确授权；仅委派扫描时返回计划，不自行执行。

## 4. 精确执行

执行每项前复核源未在计划后改变、目标目录仍存在、目标文件不存在，且解析后的源与目标都在授权边界内。遇到变化或同名目标时停止该项，保留文件并报告。

移动到已有目录；若实际需要新结构，先提出方案。更新计划内的导入、脚本或文档引用，使用当前环境支持的文件操作并正确处理空格和特殊字符。删除仅操作明确列出的路径。

## 5. 验证

读回或校验目标内容，核对清单与前后差异，确认无意外覆盖或越界改动。搜索已知旧路径引用；按文件作用运行相关的最小构建、导入或链接检查。不能完成的验证和未处理项单独列明。

报告已移动、已删除、保留与待处理项；无合理候选时说明无需变更。
