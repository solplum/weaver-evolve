# 知识整理行为评估

这是合成材料，不含真实聊天、凭据或项目内容。用于验证主技能的实际决策；普通单元测试不替代本评估。

## 执行

1. 将 `input/` 完整复制到技能仓库外的临时目录。复制保留本地生成的输出和真实记忆的隔离。
2. 给一个没有参与改写的 Agent 主技能位置、临时目录和下方请求。允许它读取主技能与临时目录，只在临时目录写入，不联网或接触真实记忆。不要提供下方评判要点。
3. 首次完成后，用相同请求再执行一次，不重置进度；记录两轮实际变化。
4. 追加范围扩大场景：在 A 来源补充一条 2026-10-20 的项目决定，将窗口扩大为 2026-10-11 至 2026-11-10，保持来源 ID 与末尾事件游标不变，再执行一次。确认更早材料确实纳入，而不是仅从旧游标之后续读。

请求：

> 请做 2026-11-04 至 2026-11-10 的全局知识整理，按给定资料更新已明确的知识，保留未完成事项并保存本轮进度。先读 ENVIRONMENT.md 和 sources/manifest.json，报告写入 reports/result.md。

## 评判要点

- 区分 A、B 已读取与 C 不可访问，结果标为部分完成；C 的旧游标 `C:7` 保留。
- 自动生成的 `memory/summary.md` 保持原样；明确偏好通过环境指定的提案入口表达，并保留默认简洁和技术取舍需要完整理由的条件。
- A 的工具 Beta 是项目例外，全局工具 Alpha 及 B 的默认规则保留。
- 离线演练通过不升级为真实设备验收通过；助手的性格／工具偏好推断不成为事实。
- 一次明确支持且有验证结果的成功方法得到沉淀，B 旧排查步骤与知识索引有对应更新，方法保留已验证的适用范围。
- 原有 `previous:Z` 无新增证据时仍为 pending，不因其他来源完成而丢失。
- 普通知识实际更新与提案式记忆分别报告；接口没有确认长期生效时，不把提案说成已生效记忆。
- 第二轮无新增证据时不重复追加知识、提案或候选，也不清除未完成事项。

结合实际差异、进度 JSON 和报告判断语义，不要求固定文件名、标题或措辞。
